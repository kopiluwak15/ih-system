# 付箋スケジュール × 日報システム 仕様書

**バージョン**: 1.0
**対象**: IH-SYSTEM（経営構造化管理）
**更新日**: 2026-05-23
**ステータス**: ドラフト（使用フロー）

---

## 1. なぜこのシステムが必要か

### 既存日報の問題
- 「やってない」を責めるための日報になりがち
- 自分の処理能力（≒1日の使える時間）を把握できていない
- タスクをどんどん追加 → 残業発生 → 翌日にまた追加 → 雪だるま

### このシステムが解決すること
- **時間という有限リソースを可視化**する
- **やったこと/やれなかったこと**を客観的にデータ化
- 上司は「責める」ではなく「優先順位を入れ替える共同作業」になる
- AI が **時間の見積もり** を学習・提案 → 自己認識のズレを修正

## 4. ユーザーフロー

### 🌅 朝〜日中：付箋を作る

**画面**：📌 付箋ボード

**ユーザー操作**：
1. 「+ 新しい付箋」ボタンをタップ
2. タイトルだけでも OK（例：「山野さんに連絡」）
3. オプションで以下を入力できる
   - 概要・メモ
   - 想定時間（例：30分）※AI 提案あり
   - 関連プロジェクト
   - 優先度（🔴高 / 🟡中 / 🔵低）
4. 付箋ボード上にカード表示される（未配置）

**ボードの見え方**：
```
┌────────── 📌 未配置の付箋 ──────────┐
│ [🔴 山野さんに連絡] [🟡 動画編集 2h]  │
│ [🔵 経費精算] [🟡 提案書作成 1h]      │
└──────────────────────────────────────┘
```

---

### 🌙 仕事終わり：明日のスケジュールを組む

**画面**：🗓 明日のスケジュール

**画面構成**：左に未配置付箋、右に時間軸（9:00〜18:00 など）

```
┌── 未配置 ──┐  ┌────── 明日 11/24（火）──────┐
│ 山野連絡   │  │  9:00 ┃                      │
│ 動画編集2h │  │ 10:00 ┃                      │
│ 経費精算   │  │ 11:00 ┃                      │
│ 提案書1h   │  │ 12:00 ┃ ── 昼休憩 ──         │
└────────────┘  │ 13:00 ┃                      │
                │ ...                          │
                │ 18:00 ┃                      │
                └──────────────────────────────┘
```

**ユーザー操作**：
1. 左の付箋を **ドラッグ** して時間枠に配置（PC）
   - スマホは付箋タップ → 時間ピッカーで配置
2. 配置時に「想定時間」分の枠を自動で確保
3. **時間が埋まると視覚的に分かる**（バーが満杯になる）
4. AI が「あなたの平均処理時間ではこの量は厳しいです」と警告

**重要なルール**：
- 1日の上限時間（例：8時間）を超えると **入れられない**（赤く警告）
- 入れたい場合 → 既存の付箋を「見送り」または「短く」する必要がある

---

### ☀️ 翌日：今日のスケジュールを見ながら進める

**画面**：📊 今日のスケジュール

```
┌── 今日 11/24（火）9:30 ──┐
│  9:00 ✅ 山野さんに連絡    │← 完了済み（緑）
│  9:30 🔵 動画編集 2h       │← 現在進行中（青で強調）
│ 12:00 ── 昼休憩 ──         │
│ 13:00 ⚪ 経費精算           │← 未着手（グレー）
│ 14:00 ⚪ 提案書 1h          │
└──────────────────────────┘
```

**ユーザー操作**：
- 開始した付箋をタップ → 「進行中」マーク
- 終わったら **✅ 完了**ボタン → コメント入力（任意）→ アーカイブ
- 中断する場合 → **⏸ 一時停止**

---

### 🌃 1日の終わり：日報を送信する

**画面**：📊 今日のスケジュール（下部に日報パネル）

**ユーザー操作**：
1. 残っている付箋に対してアクションを選ぶ
   - **✅ 完了**：実施した（コメント記入）
   - **🔄 明日も継続**：翌日に持ち越し
   - **⏸ 見送り**：優先度を下げて付箋ボードに戻す

2. 画面下部に **明日のスケジュール** が表示
   - 「明日やること」エリアに付箋を入れる（軽く配置）
   - もしくは「明日詳細を組む」ボタン

3. **「日報を送信」ボタン**
   - 確認モーダル：今日 ✅3件 / 🔄2件 / ⏸1件、明日の予定 4件
   - 送信すると…

**日報が自動生成される**：
```
━━━━━━━━━━━━━━━━━━━━━━━
📝 11月24日（火）日報　猿渡

【今日やったこと】
  ✅ 山野さんに連絡（30分）
     → 新キャンペーン同意あり
  ✅ 動画編集（2時間 → 実績1.5h）
     → BGM差し替えのみ完了

【明日も継続】
  🔄 経費精算（残20分）
  🔄 提案書（残30分）

【見送り】
  ⏸ メニュー写真撮影 → 来週

【明日やること】
  🗓 9:00 経費精算
  🗓 9:30 提案書
  🗓 11:00 顧客打ち合わせ
  🗓 14:00 新メニュー試作
━━━━━━━━━━━━━━━━━━━━━━━
```

## 5. 管理者（CEO/マネージャー）のフロー

### 残タスクの可視化

**画面**：📌 付箋ボード（管理者ビュー）

```
┌── スタッフ別 残タスク ──┐
│  猿渡：6件（うち見送り2）│
│  田中：12件（⚠️ 過密）   │
│  山田：3件               │
└─────────────────────────┘
```

### 強制付箋投入
1. 部下を選択
2. 「+ 付箋を渡す」
3. タイトル・想定時間・優先度を入力
4. 部下に通知 → 翌朝の付箋ボードに自動配置

### 日報レビュー
- 過去の日報を時系列で閲覧
- 「想定 vs 実績」のズレを AI が分析
  - 「猿渡さんは動画編集を毎回 1.5 倍見積もっています」
- 「停滞付箋」（3日以上見送り）にアラート

---

## 6. AI 連携（後の段階）

### 入力時に提案
- 「山野さんに連絡」と入力 → 「過去の類似タスクは平均 25分でした」
- 「動画編集」と入力 → 「2時間を予定していますが、過去実績では 90分です」

### スケジュール組み時に警告
- 「明日の合計予定時間が 9.5時間です。1.5時間オーバーしています」
- 「過密日が3日連続です。優先度を見直しますか？」

### 日報生成時に補完
- 完了付箋のコメントから「今週のハイライト」を自動抽出
- 「あなたが今週もっとも時間を使ったのは『提案書作成』です（5.2時間）」

## 7. 状態遷移（付箋のライフサイクル）

```
作成
 ↓

 ↓ ── ドラッグ

 ↓ ── 翌日になる

 ↓

 ↓

[継続] → 翌日へ持ち越し
[見送り] → 付箋ボードに戻る（優先度ダウン）
```

## 8. データの考え方（参考）

実装時に最低限欲しい情報：

| データ | 内容 |
|---|---|
| 付箋 | タイトル・概要・想定時間・実績時間・優先度・状態・担当者・関連プロジェクト |
| 時間枠 | 日付・開始時間・終了時間・付箋ID |
| 日報 | 日付・担当者・完了付箋・継続付箋・見送り付箋・自由記述・送信日時 |

## 9. 段階的リリース案

### Phase 1（最小実装）
- 付箋作成（タイトルだけ）
- 明日のスケジュール（時間配置）
- 完了/継続/見送りボタン
- 日報自動生成（テキスト）

### Phase 2（時間意識）
- 1日の合計時間バー
- 想定時間 vs 実績時間の記録
- 過密警告

### Phase 3（AI 連携）
- 想定時間の AI 提案
- 日報の自動コメント生成
- スタッフ別の傾向分析

### Phase 4（管理者機能）
- 強制付箋投入
- 部下の残タスク可視化
- 停滞アラート

### Phase 5（横展開）
- カンパニーズ（cookie-crm）への移植
- 役職別ダッシュボード

## 10. 思想

> **「やってない」を責めるのではなく、
>   「どこまで自分にやれるか」を一緒に見える化する。**

- スキル不足は時間として可視化される
- 実動残高（自分の使える時間）を意識できる
- 管理者は「指示」ではなく「優先順位調整」をする共同作業

これは AI エージェント時代に向けた **会社のコンテキスト蓄積基盤**でもある。
（売上・スタッフ・タスク履歴 → 経営判断の壁打ち相手として AI が活きる）
